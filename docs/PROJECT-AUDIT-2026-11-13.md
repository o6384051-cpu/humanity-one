# مراجعة HUMANITY ONE — 13 نوفمبر 2026

## ما يعمل في النسخة الحالية (main)
- واجهة عربية RTL ومركز محادثة متصل بمزود متوافق مع OpenAI عبر AI_API_KEY أو OPENAI_API_KEY.
- إدارة مؤسس/مشرفين بجلسة Cookie محمية وJWT_SECRET، وتأسيس مؤسس لمرة واحدة عبر FOUNDER_SETUP_SECRET.
- فريق وكلاء تجريبي من ثلاث مراحل متتابعة، لكنه يستخدم النموذج نفسه ولا يملك أدوات أو بحثًا خارجيًا.
- ذاكرة ومحادثات ومبادرات ومهام محلية في المتصفح.
- إعداد SEO أساسي وsitemap وrobots حسب طلب الدمج السابق.

## فجوات مؤكدة
1. سوق العمل ومركز الفرص كانا في PR #6 المسودة ولم يكونا في main.
2. صفحات التقارير والإعدادات كانت روابط غير موجودة.
3. صفحة المعرفة كانت عنصرًا شكليًا بلا محتوى قابل للبحث.
4. لا توجد حسابات عامة أو مزامنة سحابية للمبادرات والمهام والذاكرة والمحادثات.
5. لا يوجد بحث حي داخل التطبيق أو استشهادات مصدرية آلية.
6. لا يوجد تحقق خارجي من أصحاب العمل؛ المراجعة اليدوية ليست إثبات هوية.
7. حدود المعدل في الخادم الحالي لكل instance وليست حدودًا عالمية مشتركة.
8. لا يوجد نظام إشعارات حقيقي أو صندوق رسائل مباشر.
9. لا توجد اختبارات end-to-end موثقة لتدفقات المستخدم.
10. تشغيل ميزات سوق العمل يتطلب تطبيق SQL migrations على قاعدة الإنتاج بعد مراجعة حالة قاعدة البيانات.

## ما أُضيف في PR #10
- صفحات الفرص والوظائف ونشر إعلان ومتابعة طلبات صاحب العمل.
- صفحات الخطة الشخصية والسيرة الذاتية وتخطيط المشروع الصغير.
- صفحة مراجعة إعلانات الوظائف وطلبات المتقدمين مرتبطة بجلسة الإدارة بدل JOB_MODERATION_TOKEN.
- حدود طلبات ومعدل أولية لواجهات إنشاء الوظائف والتقديم.
- نماذج Prisma وترحيلات SQL إضافية، دون تشغيل ترحيل قاعدة الإنتاج تلقائيًا.
- حد لحجم محادثة AI وحد أعلى لمخرجات النموذج لتقليل إساءة الاستخدام والتكلفة.
- دعم اختيار نموذج منفصل لكل مرحلة عبر AI_PLANNER_MODEL وAI_SPECIALIST_MODEL وAI_REVIEWER_MODEL؛ إذا لم تضبط هذه المتغيرات تظل المراحل على AI_MODEL نفسه.
- صفحات التقارير والإعدادات ومكتبة مصادر أساسية، مع توضيح أن الأرقام والبيانات محلية.
